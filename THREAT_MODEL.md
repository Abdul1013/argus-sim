
**Title:** ARGUS Architecture Threat Model (STRIDE)
**Scope:** Telemetry ingestion and C2 communication between edge autonomous units (UGVs/UAVs) and the central C2 broker.

| **Threat Category**                                          | **The Vector / Threat (How they attack)**                                                                       | **The Argus Mitigation (How I stopped it)**                                                                                                                                                                     |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Spoofing**(Impersonating a node)                           | Adversary attempts to connect to the C2 network by impersonating a valid autonomous unit (e.g.,`ugv-alpha`).         | **mTLS (Mutual TLS):**Broker strictly requires a valid X.509 client certificate signed by the internal Root CA. Connections without valid certs are terminated at the transport layer before MQTT payloads are parsed. |
| **Tampering**(Modifying Data in transit)                     | Man-in-the-middle (MITM) intercepts the radio/network link to alter GPS telemetry or inject malicious flight commands. | **In-Transit Encryption:**All MQTT communication is forced over TLS 1.2/1.3. Payloads cannot be modified without breaking the cryptographic hash.                                                                      |
| **Repudiation**(Logging/ dennying an action)                 | An unauthorized user or rogue node executes a command, and there is no proof of who did it.                            | **Identity-Bound Actions:**Because every node requires a unique certificate, every connection log in Mosquitto is cryptographically tied to a specific hardware identity.                                              |
| **Information Disclosure(Eaves dropping)**                   | Adversary eavesdrops on the C2 frequency to track drone locations or monitor operational status.                       | **Transport Encryption + Closed Ports:**The broker drops any unencrypted traffic (Port 1883 is closed; only 8883 is open). The data stream is unreadable without the CA's private keys.                                |
| **Denial of Service (DoS){Crashing the pipeline}**           | Adversary floods the broker with connection requests to overload the C2 system and blind the operator.                 | **Network IDS (Suricata):**Rules configured to detect and flag stateless TCP floods on port 8883, acting as an early warning for automated IP banning (Fail2Ban/iptables implementation pending).                      |
| **Elevation of Privilege (`Gaining Unauthorized Access`)** | A compromised edge drone attempts to publish commands to*other*drones instead of just reporting its own telemetry.   | **Broker Access Control (Next Phase):**(Acknowledge future work) Transitioning to strict MQTT ACLs where client certs are mapped to specific publish/subscribe topic restrictions.                               |
